# 启动警告与健康忠告（引擎渲染，作者只给布尔值）

> 用途：把"开屏那几行字"从作者手工贴图里解放出来。作者只决定**开不开、写什么**，
> 排版、字号、居中、等比、字体收字全由引擎包办。

## 1. 已有什么（核对实录）

| 版本 | 状态 | 位置 |
|---|---|---|
| Rust Bevy 版 | **有完整实现**，文档也在 | `rust-bevy-endless-corridor/src/warnings.rs`、`docs/features.md` |
| Python 版 | 本机未找到（可能已删或在别处） | — |
| 本仓（玄铁 2D 原型） | **尚无**，需按本文落地 | — |

Rust 版的实际结构（值得照搬的部分）：

```json
{
  "global": { "enable_warnings": true, "default_language": "zh_CN" },
  "warnings": [
    { "id": "epilepsy", "title": "光敏性癫痫警告", "description": "…", "enabled": true },
    { "id": "scare",    "title": "惊吓提醒",       "description": "…", "enabled": true },
    { "id": "bloody",   "title": "血腥暴力提醒",   "description": "…", "enabled": true }
  ],
  "health_advice": { "enable_china_mainland": true, "text": "…", "position": "after_warnings" }
}
```

也就是**你要的那个布尔值**：`enable_china_mainland`，默认 `true`，文案可换，缺文件自动生成默认。
`docs/features.md` 里另有一条更好的设想：把忠告**变小、颜色变淡、移到屏幕下方慢慢提示**，
而不是怼一整屏——这条比"贴一张图"体面得多，落地时优先。

⚠️ Rust 版默认文案里有个错字：`拒接盗版游戏` 应为 **`拒绝盗版游戏`**。照搬时别把错字一起搬。

## 2. 为什么同人作品常出现繁体

规范原文是**简体**（2003 年新闻出版总署要求，中国大陆出版游戏开屏必备）。繁体出现在同人里，
一般是这几种来源，都不是"规定要求繁体"：

1. **抄了繁体模板**：从港台代理版、繁体补丁、别人的载入界面上抄下来，简繁转换过一遍
   （`拒絁`/`遊戯` 这类半转换痕迹很常见）。
2. **字体只有繁体字形**：用标楷体/新细明体这类繁体字体渲染简体字符串，某些字
   （骨、直、具、為）字形就偏繁体，看起来像繁体文。
3. **字体缺字**：繁体字体里没有简体码位 → 回退或方框。我们自己的已知坑同理：
   **没进字体参考串的字显示问号**（`AGENTS.md` 已知坑 4）。

台湾/香港并**没有**"健康游戏忠告"这套强制文本；他们有分级标示（`遊戲軟體分級管理辦法`）。
所以"繁体忠告"基本是搬运与字体问题，不是地区规定。

## 3. 本引擎的口径（落地时要遵守）

- **默认简体、默认开启**：`健康忠告.启用 = 真`，文案与 Rust 版一致（改掉错字）。
- **文案进 JSON，不进 `.xt`**：与"剧情不进源码"同一条理由（`AGENTS.md`）。
- **字体参考串必须自动收全文**：忠告文本、三条警告标题与描述全部拼进 `建字体` 的参考串，
  否则开屏就是一片问号——这是本仓已经踩过的坑。
- **等比**：开屏背景图走 `docs/素材与画面约束.md` 的比例槽位，禁止拉伸。
- **癫痫警告与闪图联动**：剧情数据里出现闪图 → 引擎**自动打开**癫痫警告，
  作者不用记得（呼应「默认即合格」）。闪图本身另有 0.3 秒 / 3 次每秒的钳制。
- **可关**：设置里给 `减少闪图`、`跳过开屏警告`（跳过只影响本次，不持久化）。
- **位置选项**：`整屏` / `底部淡字`（默认建议后者，观感最好、也不挡内容）。

## 3.5 它在这里是"仪式"，不是合规

同人作品多半网盘分发、没有版号、内容本来也过不了审——那种场合贴一段健康忠告，
实际作用是**照搬形式**，不构成任何合规。引擎收录它，理由是另一件事：

- 贴图版的忠告几乎都是**拉伸的、字体糊的、繁简混的**，在解说视频里被放大看最刺眼；
- 引擎渲染的文本**等比、清晰、简繁自洽**，作者一行配置就有了；
- 而且它是"开屏第一屏"，**画面观感的第一印象就在这几秒**。

所以口径是**提供渲染、不做判定**：引擎不评估内容能否过审、不认定合法性，
只把"想显示的人"显示得好看些。反过来也别把"内置忠告"当成合规背书（见第 4 节）。

## 4. 合批：最多两屏，别一图一条

现状是**每样东西一张图、各自淡入淡出**：作者网名一张、健康忠告一张、同人声明一张、
血腥暴力提示一张……四个五秒，玩家还没玩就先等十几秒，而且每条都得重新"入戏"。
引擎应该**把同类合成一屏**，让信息一次读完。

### 4.1 分两组，最多两屏

| 屏 | 组名 | 放什么 | 时长 |
|---|---|---|---|
| 第 1 屏 | **内容提示** | 闪图 / 血腥暴力 / 惊吓 / 光敏性癫痫 / 其他不适内容 | 3~4 秒 |
| 第 2 屏 | **声明与致谢** | 作者与团队、同人/非官方声明、素材来源署名、健康忠告（底部淡字） | 3~4 秒 |

规则：

- **只有一组内容时合成一屏**（没写暴力就不开"内容提示"那一屏）；
- 两屏合计**不超过 8 秒**，任意键跳过（跳过只影响本次）；
- 屏内文字**逐行渐显**（每行间隔 200~300 ms），**不要逐条淡入淡出**；
- 屏与屏之间只做**一次**淡出淡入，不要每行都闪；
- 忠告永远放最后一屏的**底部淡字**，不与正文抢视线。

### 4.2 内容提示由数据推出来，作者只填布尔

作者最容易忘的就是"我这版加了闪图，但忘了写癫痫提示"。所以**不要让他手写这一屏**：

```json
{
  "作者": "<作者名>",
  "同人声明": "本作为非官方同人作品，与原著权利方无关",
  "内容提示": { "闪图": true, "血腥": true, "惊吓": true, "光敏性癫痫": "自动" },
  "健康忠告": { "启用": true, "位置": "底部淡字" }
}
```

- `内容提示` 的每一项由**内容标记**驱动（剧情/素材里出现闪图就置 `闪图`，出现血液贴图就置 `血腥`），
  引擎汇总后生成第一屏的句子，作者**不需要逐条写文案**；
- `光敏性癫痫: "自动"` = 只要 `闪图` 为真就自动出这一行（同时打开第 2 节的安全钳制）；
- `同人声明` 与 `作者` 缺省时给中性占位（"本作为非官方同人作品" / "作者未署名"），**不报错**。

这样"是否含 X"这个问题只回答一次（在数据里），而不是在四张图上各答一次。

## 5. 边界（别越界）

引擎提供的是**渲染能力**，不是合规承诺。有版号/审批需求的，仍按 `docs/授权与合规问答.md`
的口径：本仓库不代办、不认定、不兜底。**内置忠告 ≠ 已合规**，别在对外文档里那样写。
