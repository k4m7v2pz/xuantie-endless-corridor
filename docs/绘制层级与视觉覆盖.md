# 绘制层级与视觉覆盖

本文整理「无尽回廊」的画面分层：从地板到终端一共几层、各层职责、谁接收输入，
以及迷雾（记忆）与黑暗（当下视野）两套视觉覆盖的关系。

**来历**：这套东西先在 Rust Bevy 版（`rust-bevy-endless-corridor`）成型，
其前身是一个已删除的 Python 版；Bevy 版里的分层设计只散落在代码注释中
（`src/fog_of_war.rs` 文件头、`docs/dual-window-rendering.md`），没有独立成文。
这里把它抽出来，并落到玄铁版的实际能力上，避免随某个仓库一起消失。

参数取自 Rust 版源码（`src/constants.rs`、`src/darkness.rs`、`src/fog_of_war.rs`）。

---

## 1. 前提：2D 里没有 z 缓冲，顺序就是层级

Bevy 有 `Transform::z` 可以真的排序；raylib 没有 z 缓冲，**只有绘制先后**，
后画的盖住先画的。所以这里的「层级」在玄铁版不是数字，而是**一次绘制循环里的调用顺序**。

推论：层级必须在一处集中定义。如果每个函数自己到处画（这里画个 HUD、那里画个提示），
迟早互相压住，而且改一层要翻遍全文件。正确做法是只留一个入口：

```xt
函 绘一帧() {
    绘世界底层()      // 1 地板、墙面
    绘世界物件()      // 2 图块、书架、门
    绘角色()          // 3 主角、怪物
    绘视觉覆盖()      // 4 迷雾、黑暗、光锥
    绘常驻HUD()       // 5 血量、任务提示
    绘模态层()        // 6 主菜单、ESC 暂停、设置、存档
    绘调试HUD()       // 7 FPS、坐标
    绘终端()          // 8 命令控制台
}
```

## 2. 八个绘制阶段

| 序 | 层 | 内容 | 接收输入 |
|---|---|---|---|
| 1 | 地图底层 | 地板纹理、墙面、地砖缝 | — |
| 2 | 世界物件 | 图块、书架、门、箱子、地面上的血迹 | — |
| 3 | 角色 | 主角、怪物、光源载体 | 世界输入（移动、交互） |
| 4 | 视觉覆盖 | 迷雾（记忆）、黑暗与光锥（当下视野） | — |
| 5 | 常驻 HUD | 血量、当前目标（「找到钥匙」这类引导） | 不吞输入 |
| 6 | 模态层 | 主菜单、ESC 暂停、设置、存档、事件树 | **吞**世界输入 |
| 7 | 调试 HUD | FPS、玩家坐标、状态机当前值 | 不吞输入 |
| 8 | 终端 | CS 系命令台，可敲命令改状态 | **独占**输入 |

原先按「七层」谈的时候，第 4 层是算在世界层内部的（视觉覆盖属于游戏画面的一部分）。
拆成八行只是为了把「覆盖层」单独拿出来说清楚，层级关系没有变：
覆盖层在世界物件之上、HUD 之下。

**主角不单独抬到世界之上。** 主角和图块同属世界层；只有俯视/斜俯视才需要按 y 排序
决定谁遮谁。正侧面走廊不需要，主角画在物件之后即可。
若将来要「前景立柱遮住上半身」，那是世界层内部再加一个前景子层，不是把主角提到 HUD 下面。

## 3. 视觉覆盖：三种「雾」，本项目只要两种

### 3.1 先分清楚，名字像但没关系

| | 物理雾（mist） | 探索迷雾（shroud） | 当前视野（darkness） |
|---|---|---|---|
| 像什么 | 走廊尽头那层灰白 | 从没去过的地方一片黑 | 没光的地方全黑 |
| 信息量 | 有轮廓、无细节 | 零 | 零 |
| 解除方式 | 靠近才有光看清，走开又糊 | 走过就永久记住 | 手电照到才亮，走开就暗 |
| 需要存档吗 | 不需要 | **需要**（已揭示集合） | 不需要 |

物理雾在现实中不是「挡住东西」，而是**降低对比度**：远处物体的亮度被雾自身的散射亮度淹没，
所以看不见；近处雾薄，还分得清轮廓。雾颗粒不发光，它只把别处的光散射进你眼睛——
所以晚上起雾时你看不见雾，一旦有光源，雾立刻以光晕/光柱显形。这决定了「灯光破雾」
在物理上也是对的：光把物体亮度抬起来，与雾的亮度差变大，于是雾在光范围内变薄；
但光越远越弱，超出范围照样白茫茫。**结果就是光柱，不是整片雾消失。**

### 3.2 为什么本项目不做探索迷雾

RTS 的对照（设计讨论中确定的版本）：红警 2 是**单层**——地形与单位要么全显示、
要么全不显示，没有「已探索但当前无视野」的中间态；红警 3 是**两层**，但开局就把地形和
中立建筑全给玩家，只有敌方动态单位需要当前视野。

这说明连 RTS 也在砍掉「静态地形需要重新揭示」这一层：地形是常量，反复去揭只是重复劳动，
还妨碍操作。真正需要「看」的只有动态单位——那是多人博弈的信息需求。

本项目是单人线性走廊，两个前提都不成立：

- 走廊只有一条主线，没有「从不同方向再进一次」，记忆层没有信息增量；
- 没有需要藏起来的动态单位，敌方动向不构成博弈；
- 剧情向游戏里，玩家的信息成本应该花在**读懂文本和解谜**上，不该花在点亮地图。

所以：**探索迷雾不立项**。只保留「当前视野（darkness）」与「物理雾（mist）」，
两者都只作用于当前这一帧，**没有任何需要写进存档的视觉状态**——
顺带避免了「读档后地图亮一半」这类问题。

若将来真要做探索，按红警 2 那种「看见就永久记住、不做实时回退」即可，比双层简单。


这是 Rust 版里最容易被误解的一处 —— 迷雾和黑暗不是同一个东西：

| | 迷雾 Fog of War | 黑暗 Darkness |
|---|---|---|
| 语义 | **记忆**：走过就永久揭示，没走过的永远黑 | **当下视野**：手电照到才亮，走开就暗 |
| 单位 | 按 tile（64px 网格） | 连续（圆 + 扇形） |
| 持久化 | `RevealedTiles` 集合随存档保存 | 不持久化，每帧重算 |
| 相对层级 | 在黑暗之下 | 在迷雾之上 |

（Rust 版当初还实现了探索迷雾，并在文件头写下：fog=2.5、darkness=3~4，
手电筒能刺穿迷雾照亮未探索区。按本节的结论，这一层在玄铁版不立项，
但这段「覆盖层也有上下顺序」的判断保留下来参考。）

### 3.3 黑暗层由三样东西组成

| 部件 | 参数（Rust 实测值） | 作用 |
|---|---|---|
| 环境暗圆 | 半径 180，z=3.0 | 玩家周身一圈始终勉强可见 |
| 手电锥 | 半径 360、半角 ±45°（π/4）、32 段扇形、`rgba(1.0, 0.95, 0.7, 0.28)` | 前方暖黄光锥，略偏黄 |
| 怪物光 | z=3.5 | 怪物自带的一点光，插在两者之间 |

合起来的效果是「黑幕中间一小圈能看清，前方一锥能照亮」，
而不是均匀变暗 —— 恐怖游戏要的是「看不全」，不是「看不清」。

## 4. 玄铁版怎么落

玄铁版没有 z，按顺序落地就是：**物理雾 → 环境暗圆 → 怪物光 → 手电锥**
（没有迷雾网格这一环，按 3.2 不立项）。

绘制能力上够用，渲染库已实测暴露这些：

- `R.绘三角(x1,y1,x2,y2,x3,y3,r,g,b,a)` —— 手电锥可以用 32 个三角形拼扇形
- `R.绘圆` / `R.绘椭圆` —— 环境暗圆
- `R.绘多边形(cx,cy,边数,半径,旋转,r,g,b,a)` —— 规则多边形的替代
- `R.GenGradientTexture(...)` —— 生成径向渐变纹理，用来做「从中心向外衰减」的柔边
- `R.开始裁剪(x,y,w,h)` / `R.结束裁剪()` —— 局部区域裁剪

### 4.1 一个必须提前认清的限制：没有「挖洞」

raylib 不支持「在暗层中间挖一个透明洞」这种合成模式。所以覆盖层不能这样做：

```
先画满黑  →  在中间擦掉一块（做不到）
```

只能是「在暗底上叠亮」：

```
先画暗底（接近黑）  →  在亮区叠上接近地面色的亮色
```

这就要求亮层颜色必须贴近地面色，否则玩家看到的是一个「发光的圆盘」而不是「被照亮的地面」，
这比全黑还出戏。当前实现用的是四圈同心圆近似（在游戏画面里能看到的那几层圆），
效果是「能看清中间的轮廓但边缘很硬」。

### 4.2 两条可选路线

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A 同心圆近似（现用） | 由外向内叠若干层半透明亮圆 | 简单、每帧固定几次 `绘圆` | 边缘生硬，看得出圈 |
| B 距离场衰减 | 每帧算画面每点到光源的距离，按距离定 alpha | 边缘平滑，接近真光照 | 需要逐像素/密网格，实现重 |

现代机器上 B 也跑得动，但它需要先有「离屏画布 + 逐像素写」的能力，
而渲染库目前只暴露了图形绘制，没有暴露画布级像素写入。**所以现阶段继续用 A**，
等哪天渲染库补上画布接口再考虑 B。A 的改善空间是「加圈数 + 让每圈 alpha 变化更细」，
先做这个比换方案划算。

## 5. 输入路由

层级决定「看得见」，输入路由决定「按键听谁的」。两者要一一对应，否则会出诡异 bug：

- 终端打开时敲 `w`，角色往前走 —— 输入没按层切断。
- 暂停层弹着，玩家按 `1` 选到了分支选项 —— 模态层没吞世界输入。

规则只有一条：**每帧先算「当前输入归谁」，再分发**，不要在各更新函数里各自读键。

优先级：**终端 > 模态层 > 游戏世界**

| 层 | 吞什么 | 保留什么 |
|---|---|---|
| 终端 | 全部按键（含字母、数字、空格、方向） | ESC / 终端自己的关闭键 |
| 模态层 | 移动、交互、剧情推进 | ESC（关层）、层内导航键（上下/回车） |
| 调试 HUD | 不吞 | — |

实现要点：

1. 用一个全局变量 `输入归属 = 终端 / 模态 / 世界`，在更新阶段最开始定好。
2. 世界层的 `更新走()`、`更新锁()` 只在 `输入归属 == 世界` 时才跑 ——
   这同时实现了「冻结逻辑」：暂停层开着，世界不更新，但**仍然每帧绘制**，
   玩家能看到自己停在哪一刻。冻结更新、不冻结渲染，这是 RPG Maker 那套的做法。
3. 终端取字符走 `R.获字符()`（`XT_GetCharPressed`），它配合 IME 能收中文；
   不要用键码硬比 —— 中文命令/中文参数靠键码是收不到的。

## 6. 现状对照（玄铁版）

| 项 | 状态 |
|---|---|
| 八层顺序 | 部分（世界 + 正文/HUD + 标题屏），未集中成一个入口 |
| 探索迷雾（记忆） | 不立项，见 3.2 |
| 黑暗 / 手电锥 | 未实现（用的是同心圆光圈） |
| 物理雾 | 未实现 |
| 模态层（主菜单 / ESC 暂停） | 未实现；ESC 现在直接退出 |
| 调试 HUD | 未实现 |
| 终端 | 未实现 |

下一步优先级建议：**模态层**（有明确需求、改动小、能立刻验证）→ **黑暗覆盖**（视觉收益最大）
→ **物理雾** → **调试 HUD** → 终端。
