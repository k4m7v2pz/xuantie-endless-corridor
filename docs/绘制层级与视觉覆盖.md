# 绘制层级与视觉覆盖

本文整理「无尽回廊」的画面分层：从地板到终端一共几层、各层职责、谁接收输入，
以及迷雾（记忆）与黑暗（当下视野）两套视觉覆盖的关系。

**来历**：这套东西先在 Rust Bevy 版（`rust-bevy-endless-corridor`）成型，
其前身是一个已删除的 Python 版；Bevy 版里的分层设计只散落在代码注释中
（`src/fog_of_war.rs` 文件头、`docs/dual-window-rendering.md`），没有独立成文。
这里把它抽出来，并落到玄铁版的实际能力上，避免随某个仓库一起消失。

参数取自 Rust 版源码（`src/constants.rs`、`src/darkness.rs`、`src/fog_of_war.rs`）。

---

## 1. 前提：2D 里没有 z 缓冲，顺序就是层级

Bevy 有 `Transform::z` 可以真的排序；raylib 没有 z 缓冲，**只有绘制先后**，
后画的盖住先画的。所以这里的「层级」在玄铁版不是数字，而是**一次绘制循环里的调用顺序**。

推论：层级必须在一处集中定义。如果每个函数自己到处画（这里画个 HUD、那里画个提示），
迟早互相压住，而且改一层要翻遍全文件。正确做法是只留一个入口：

```xt
函 绘一帧() {
    绘世界底层()      // 1 地板、墙面
    绘世界物件()      // 2 图块、书架、门
    绘角色()          // 3 主角、怪物
    绘视觉覆盖()      // 4 迷雾、黑暗、光锥
    绘常驻HUD()       // 5 血量、任务提示
    绘模态层()        // 6 主菜单、ESC 暂停、设置、存档
    绘调试HUD()       // 7 FPS、坐标
    绘终端()          // 8 命令控制台
}
```

## 2. 八个绘制阶段

| 序 | 层 | 内容 | 接收输入 |
|---|---|---|---|
| 1 | 地图底层 | 地板纹理、墙面、地砖缝 | — |
| 2 | 世界物件 | 图块、书架、门、箱子、地面上的血迹 | — |
| 3 | 角色 | 主角、怪物、光源载体 | 世界输入（移动、交互） |
| 4 | 视觉覆盖 | 迷雾（记忆）、黑暗与光锥（当下视野） | — |
| 5 | 常驻 HUD | 血量、当前目标（「找到钥匙」这类引导） | 不吞输入 |
| 6 | 模态层 | 主菜单、ESC 暂停、设置、存档、事件树 | **吞**世界输入 |
| 7 | 调试 HUD | FPS、玩家坐标、状态机当前值 | 不吞输入 |
| 8 | 终端 | CS 系命令台，可敲命令改状态 | **独占**输入 |

原先按「七层」谈的时候，第 4 层是算在世界层内部的（视觉覆盖属于游戏画面的一部分）。
拆成八行只是为了把「覆盖层」单独拿出来说清楚，层级关系没有变：
覆盖层在世界物件之上、HUD 之下。

**主角不单独抬到世界之上。** 主角和图块同属世界层；只有俯视/斜俯视才需要按 y 排序
决定谁遮谁。正侧面走廊不需要，主角画在物件之后即可。
若将来要「前景立柱遮住上半身」，那是世界层内部再加一个前景子层，不是把主角提到 HUD 下面。

## 3. 视觉覆盖：三种「雾」，本项目只要两种

### 3.1 先分清楚，名字像但没关系

| | 物理雾（mist） | 探索迷雾（shroud） | 当前视野（darkness） |
|---|---|---|---|
| 像什么 | 走廊尽头那层灰白 | 从没去过的地方一片黑 | 没光的地方全黑 |
| 信息量 | 有轮廓、无细节 | 零 | 零 |
| 解除方式 | 靠近才有光看清，走开又糊 | 走过就永久记住 | 手电照到才亮，走开就暗 |
| 需要存档吗 | 不需要 | **需要**（已揭示集合） | 不需要 |

物理雾在现实中不是「挡住东西」，而是**降低对比度**：远处物体的亮度被雾自身的散射亮度淹没，
所以看不见；近处雾薄，还分得清轮廓。雾颗粒不发光，它只把别处的光散射进你眼睛——
所以晚上起雾时你看不见雾，一旦有光源，雾立刻以光晕/光柱显形。这决定了「灯光破雾」
在物理上也是对的：光把物体亮度抬起来，与雾的亮度差变大，于是雾在光范围内变薄；
但光越远越弱，超出范围照样白茫茫。**结果就是光柱，不是整片雾消失。**

### 3.2 三层都做，但都是可开关的引擎模块

**这是引擎，不是一部作品。** 判断某一层要不要，不能拿当前这部线性走廊剧情当依据，
要看「引擎要不要支持这种玩法」。结论是三层都要，只是默认值不同、由剧情配置决定：

| 模块 | 默认 | 谁需要它 |
|---|---|---|
| 当前视野（darkness） | 开 | 几乎所有场景：没光就看不见 |
| 物理雾（mist） | 关（浓度 0） | 室外、走廊尽头、有纵深感的场景 |
| 探索迷雾（shroud） | 关 | 房间反复进出、开门找钥匙、需要跑回头路的地图 |

RPG Maker 那类结构（一个房间进出好几趟、钥匙在另一头、地图要来回跑）恰恰是探索迷雾
最有用的时候：跑过的走廊不必再黑一遍，否则每次回头都是白跑。这时候迷雾不是负担而是省事。

配置形态（每幕可以不同，写在 `剧情/幕NN.json` 里）：

```json
"视觉": { "当前视野": true, "物理雾": 0.35, "探索迷雾": false }
```

`物理雾` 是浓度（0 = 关），另两个是开关。

**连带契约**：探索迷雾一旦开启，引擎必须同时提供「已揭示集合」的存档接口
（Rust 版是 `RevealedTiles` 存进 `save.rs`）。这是引擎级契约，不是某部剧情自己的事——
要么不做，要做就得连存档一起做，做半截（读档后探索成果全丢）比不做更糟。

RTS 的对照可以当参考，但不该当依据：红警 2 是单层（地形与单位要么全显示要么全不显示），
红警 3 是双层、开局把地形全给玩家、只有动态单位需要视野。它们砍掉的是「静态地形要反复揭示」，
因为多人博弈里地形是常量、反复揭只是重复劳动；但单人跑图游戏里地形不是常量——
玩家的记忆会忘，雾就是在替玩家记。所以取舍取决于玩法，不取决于「RTS 都这么干」。

若将来要做，按红警 2 那种「看见就永久记住、不做实时回退」即可，比双层简单。


这是 Rust 版里最容易被误解的一处 —— 迷雾和黑暗不是同一个东西：

| | 迷雾 Fog of War | 黑暗 Darkness |
|---|---|---|
| 语义 | **记忆**：走过就永久揭示，没走过的永远黑 | **当下视野**：手电照到才亮，走开就暗 |
| 单位 | 按 tile（64px 网格） | 连续（圆 + 扇形） |
| 持久化 | `RevealedTiles` 集合随存档保存 | 不持久化，每帧重算 |
| 相对层级 | 在黑暗之下 | 在迷雾之上 |

（Rust 版当初还实现了探索迷雾，并在文件头写下：fog=2.5、darkness=3~4，
手电筒能刺穿迷雾照亮未探索区。按本节的结论，这一层在玄铁版不立项，
但这段「覆盖层也有上下顺序」的判断保留下来参考。）

### 3.3 黑暗层由三样东西组成

| 部件 | 参数（Rust 实测值） | 作用 |
|---|---|---|
| 环境暗圆 | 半径 180，z=3.0 | 玩家周身一圈始终勉强可见 |
| 手电锥 | 半径 360、半角 ±45°（π/4）、32 段扇形、`rgba(1.0, 0.95, 0.7, 0.28)` | 前方暖黄光锥，略偏黄 |
| 怪物光 | z=3.5 | 怪物自带的一点光，插在两者之间 |

合起来的效果是「黑幕中间一小圈能看清，前方一锥能照亮」，
而不是均匀变暗 —— 恐怖游戏要的是「看不全」，不是「看不清」。

### 3.4 演出态：电影胶片（回忆 / 前情提要）

它**不属于三种「雾」中的任何一种**。雾是持续的空间状态（一直在，随玩家移动变化）；
电影胶片是有始有终的**演出态**（进入 → 维持 → 退出，期间叙事模态变了）。

判定它值不值得做，关键不在遮幅 —— 上下两条黑边谁都会画。它的价值在于
**给画面盖一个「这不是现在」的签章**：玩家知道眼前这段是回忆、是录像、是前情提要，
不是此刻正在发生的事。恐怖游戏里这层签章有两个正经用途：不可靠叙述，
以及"交代你为什么会在这里"而不必让玩家重玩。

#### 两件事必须分开配

| 件 | 归属层 | 负责什么 |
|---|---|---|
| 遮幅 + 胶片质感 | 视觉覆盖（阶段 4） | 只改"看起来像什么" |
| 输入语义 | 模态层（阶段 6） | 回忆期间能不能走动、开门 |

只做前者不做后者，玩家会在回忆画面里四处跑，画面一动，"这是回忆"的签章立刻失效
——观众会当成实时场景。这是这套效果最容易配错的地方。
反过来，若某段只是「旁白式前情提要」、允许玩家继续操作，那就**不该给遮幅**，
给了反而像误入一个没做完的过场。

#### 遮幅本身

- 高度按**窗口高度比例**算（如 12%），不写死像素，换窗口尺寸不用改。
- 用**遮挡**不用裁剪：`绘矩形` 盖黑，内容仍在下面继续画。
  裁剪会把内容裁掉，且本项目正文区坐标是按整屏算的，裁完再还原容易错位。
- 进出要**动画**（几帧滑入/滑出）。瞬切像 UI 弹窗，渐收才像镜头。

#### 胶片质感，按成本从低到高

| 效果 | 做法 | 成本 |
|---|---|---|
| 色偏（暖黄） | 整屏半透明色块 | 低。**限制**：渲染库未导出混合模式，做不到真正"降饱和"，只能覆盖近似 |
| 曝光闪烁 | 整屏半透明白/黑，alpha 低频调制 | 低 |
| 划痕 | 细长矩形，随机 x、随机透明度、偶发几帧 | 低 |
| 颗粒 | **预生成一张噪声 PNG**，每帧随机偏移 + 半透明平铺 | 中（要进 assets，是本项目第一张非图块素材） |
| 帧抖动（画面整体晃 1~2px） | 需要世界层统一偏移入口 | 高。当前世界绘制全是散点坐标，没有统一变换，得先加"世界偏移"变量 |

颗粒那条是这里唯一的技术硬点：**渲染库没有离屏画布，做不了逐像素噪声**。
正解是噪声贴图 + 随机偏移，一张图同时给出"颗粒"和"画面不安定"两种观感。
每帧画几百个小点也能凑，但点会落到整数坐标上，一片整齐方点不像胶片，像马赛克。

#### 配置形态

跟界面文案同理，演出参数进剧情 JSON，不进 `.xt`。布尔值在本项目 JSON 里没有先例，
统一用数值（0 = 关，1 = 开）：

```json
"演出": { "类型": "回忆", "遮幅": 0.12, "调色": "暖黄", "颗粒": 0.35, "抖动": 0 }
```

`类型` 给默认配方（`回忆` = 遮幅 + 暗调 + 颗粒；`前情提要` = 遮幅 + 标题字；
`结局` = 遮幅 + 颗粒 + 曝光回落），单个字段可覆盖默认。

#### 它顺手补上一个已知缺口

本项目三幕之间目前要求玩家"把前两幕再过一遍"（纯文本播放器有"从第几幕开始"的选项，
2D 版没有）。**前情提要**正好是这个缺口的正解：上一幕结束 → 遮幅落下 → 两三行摘要
→ 遮幅收起 → 下一幕开始。玩家不必重玩，也不至于忘了前面发生过什么。
这也正好符合"关键事实要在直白层至少出现一次"那条规则 —— 摘要在直白层。

#### 与其他层的关系

- 与三种雾**不冲突、可叠加**。阶段 4 内部的顺序：雾 → 遮幅 → 颗粒。
  颗粒盖在最上面，理由是胶片颗粒指"胶片本身脏了"，不该被场景光照影响。
- 它吞不吞世界输入，不由它自己决定，而由模态层决定（见上面"两件事必须分开配"）。

## 4. 玄铁版怎么落

玄铁版没有 z，按顺序落地就是：**物理雾 → 环境暗圆 → 怪物光 → 手电锥**
（探索迷雾本作默认关，见 3.2）。

绘制能力上够用，渲染库已实测暴露这些：

- `R.绘三角(x1,y1,x2,y2,x3,y3,r,g,b,a)` —— 手电锥可以用 32 个三角形拼扇形
- `R.绘圆` / `R.绘椭圆` —— 环境暗圆
- `R.绘多边形(cx,cy,边数,半径,旋转,r,g,b,a)` —— 规则多边形的替代
- `R.GenGradientTexture(...)` —— 生成径向渐变纹理，用来做「从中心向外衰减」的柔边
- `R.开始裁剪(x,y,w,h)` / `R.结束裁剪()` —— 局部区域裁剪

### 4.1 一个必须提前认清的限制：没有「挖洞」

raylib 不支持「在暗层中间挖一个透明洞」这种合成模式。所以覆盖层不能这样做：

```
先画满黑  →  在中间擦掉一块（做不到）
```

只能是「在暗底上叠亮」：

```
先画暗底（接近黑）  →  在亮区叠上接近地面色的亮色
```

这就要求亮层颜色必须贴近地面色，否则玩家看到的是一个「发光的圆盘」而不是「被照亮的地面」，
这比全黑还出戏。当前实现用的是四圈同心圆近似（在游戏画面里能看到的那几层圆），
效果是「能看清中间的轮廓但边缘很硬」。

### 4.2 两条可选路线

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A 同心圆近似（现用） | 由外向内叠若干层半透明亮圆 | 简单、每帧固定几次 `绘圆` | 边缘生硬，看得出圈 |
| B 距离场衰减 | 每帧算画面每点到光源的距离，按距离定 alpha | 边缘平滑，接近真光照 | 需要逐像素/密网格，实现重 |

现代机器上 B 也跑得动，但它需要先有「离屏画布 + 逐像素写」的能力，
而渲染库目前只暴露了图形绘制，没有暴露画布级像素写入。**所以现阶段继续用 A**，
等哪天渲染库补上画布接口再考虑 B。A 的改善空间是「加圈数 + 让每圈 alpha 变化更细」，
先做这个比换方案划算。

## 5. 输入路由

层级决定「看得见」，输入路由决定「按键听谁的」。两者要一一对应，否则会出诡异 bug：

- 终端打开时敲 `w`，角色往前走 —— 输入没按层切断。
- 暂停层弹着，玩家按 `1` 选到了分支选项 —— 模态层没吞世界输入。

规则只有一条：**每帧先算「当前输入归谁」，再分发**，不要在各更新函数里各自读键。

优先级：**终端 > 模态层 > 游戏世界**

| 层 | 吞什么 | 保留什么 |
|---|---|---|
| 终端 | 全部按键（含字母、数字、空格、方向） | ESC / 终端自己的关闭键 |
| 模态层 | 移动、交互、剧情推进 | ESC（关层）、层内导航键（上下/回车） |
| 调试 HUD | 不吞 | — |

实现要点：

1. 用一个全局变量 `输入归属 = 终端 / 模态 / 世界`，在更新阶段最开始定好。
2. 世界层的 `更新走()`、`更新锁()` 只在 `输入归属 == 世界` 时才跑 ——
   这同时实现了「冻结逻辑」：暂停层开着，世界不更新，但**仍然每帧绘制**，
   玩家能看到自己停在哪一刻。冻结更新、不冻结渲染，这是 RPG Maker 那套的做法。
3. 终端取字符走 `R.获字符()`（`XT_GetCharPressed`），它配合 IME 能收中文；
   不要用键码硬比 —— 中文命令/中文参数靠键码是收不到的。

## 6. 现状对照（玄铁版）

| 项 | 状态 |
|---|---|
| 八层顺序 | 部分（世界 + 正文/HUD + 标题屏），未集中成一个入口 |
| 探索迷雾（记忆） | 未实现（可选模块，本作默认关） |
| 黑暗 / 手电锥 | 未实现（用的是同心圆光圈） |
| 物理雾 | 未实现 |
| 演出态（电影胶片 / 前情提要） | 未实现（见 3.4） |
| 模态层（主菜单 / ESC 暂停） | 未实现；ESC 现在直接退出 |
| 调试 HUD | 未实现 |
| 终端 | 未实现 |

下一步优先级建议：**模态层**（有明确需求、改动小、能立刻验证）→ **黑暗覆盖**（视觉收益最大）
→ **物理雾** → **调试 HUD** → 终端。

## 7. 参数速查（Rust 版原值）

```
TILE_SIZE                 64
DARKNESS_AMBIENT_RADIUS   180
DARKNESS_Z_AMBIENT        3.0
DARKNESS_Z_MONSTER        3.5
DARKNESS_Z_FLASHLIGHT     4.0
FOG_Z                     2.5
PLAYER_FLASHLIGHT_RADIUS  360
PLAYER_FLASHLIGHT_HALF_ANGLE  π/4（±45°）
DARKNESS_CONE_SEGMENTS    32
手电锥颜色                  rgba(1.0, 0.95, 0.7, 0.28)
```
