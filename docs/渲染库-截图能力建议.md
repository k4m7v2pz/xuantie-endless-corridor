# 渲染库截图能力：实测现状与改进建议

给以后做贡献时提 issue / PR 用的底稿。口径是**实测**，版本按本机
`xtc-package/lib/渲染/渲染.xt`（写作时 1.3.11）。本仓库自己怎么绕，见第 2 节。

## 1. 现状（实测）

入口只有一个：`公 函 截图(路径)`。

- **只落盘，不返回东西**：没有成功标志、没有字节、没有宽高。想校验"这张对不对"
  只能自己再读文件。
- **时机含糊**：在帧内调用正常；在帧外（世界更新里、`开始绘图` 之前）调用会打印
  `[渲染库][错误] 截图 调用时机不对:<路径>`，**但图片仍然照样保存成功**。
  错误是噪的——既拦不住，又会让人以为没截到。
- **尺寸按物理像素**：Retina 2x 出来的图是逻辑尺寸的两倍（逻辑 800×600 → 1600×1200）。
  库里另有一处注释给了"物理像素 → 逻辑单位"的换算口径，两处最好互相引用。
- **离屏可用**：`隐藏窗口` 初始化（changelog 记的 issue #155）之后，渲染与截图照常，
  批处理不弹窗——这条对我们很有用。
- **同名覆盖**：路径由调用方给，连续截会一路覆盖，序列要调用方自己编号。

## 2. 本仓库在应用层的绕法（边角料，供参考）

- `F2` 键 → `R.截图("/tmp/走廊截图.png")`：要有焦点，不适合无人值守。
- **信号文件**：每帧读 `/tmp/走廊截图.请求`，**内容一变**就截一张。
  外部 `date > /tmp/走廊截图.请求` 即可，不删文件、不抢焦点、不碰键盘。
- **自检路线**：`touch /tmp/tilemap-自检` 后按固定路线自动走，换图即截图序列，
  走完自动关窗。判据是"截图张数对不对"（三次换图三张，多一张就是门在乒乓）。

## 3. 建议（按价值排序）

**A. 返回结果对象或字节**
`截图(路径)` 回 `{成功, 路径, 宽, 高, 字节}`；另给 `截图字节(格式)` 直接回内存。
理由：校验、上传、两帧比对都要像素，不该逼调用方再读盘。

**B. 把时机契约写死、并统一**
两种都行，但要明确：① 允许帧外调用，自动截"上一帧已完成画面"；
② 明确只允许帧内，帧外直接返回失败（且**真的不保存**）。
现在"报错但成功"最坏：既不能当判据，又让人不敢用。

**C. 序列截图**
`截图序列(前缀, 上限张数)` 自动编号防覆盖；或 `截图(路径, 选项{ 编号: 真 })`。
现在做"每帧一图"的视频式取证，得调用方自己拼文件名。

**D. 区域截图**
`截图区域(横, 纵, 宽, 高, 路径)`，坐标用逻辑单位（与现有 Retina 注释同一口径）。
用途：只截 HUD、只截一格图块做回归对比，图小、diff 直观。

**E. 外部触发钩子（最想要的一条）**
让渲染进程自己监听一个"截图请求"来源（文件内容变、命名管道、或环境变量指定的路径），
命中就截。这样 CI 里"无人值守截当前帧"不需要应用层轮询 hack，
也不需要桌面截图工具（后者要屏幕录制权限，还会把无关窗口拍进去）。

**F. 失败原因文本化**
现有"调用时机不对"就是好范例，建议补齐其余路径：目录不可写、格式不支持、
GL 上下文已销毁。判据脚本要能凭文案区分"没截"和"截坏了"。

**G. 截图到纹理**
可选：截成纹理/句柄直接比较，省掉落盘。做像素级回归（比如"门框必须画在门格上"）
时，落盘-读盘的往返是主要成本。

## 4. 最小复现（提 issue 时贴这个）

```bash
# 帧外调用：会打印"调用时机不对"，但文件仍生成
# 逻辑 800×600、Retina 2x 环境下实测输出 1600×1200
```

结论一句话：**能截，但只截到文件、时机语义含糊、序列与区域都要调用方自己造**。
前三条（A/B/C）落地，做自动化验收就不用再在应用层绕。
