# 音频设计：脚步 = 脚部 × 材质

> 状态：**设计定稿，未实现**。声音本身一条都还没做（没有 WAV、没有接线），
> 这里先把口径钉死，等有闲时按「逐条试听」的方式落地（流程见最后一节）。

## 0. 为什么单独为脚步写一篇

脚步是玩家听得最多次的声音。一场十分钟的戏，走位可能触发上千次落地——
它的**性格**直接决定这个游戏"像不像"。多数游戏只做一条"穿鞋走硬地"的通铺声，
问题不在于省事，而在于一条波形反复播放，第一分钟就露出发条感。

## 1. 物理依据：三个变量决定落地声

不是玄学，落地声由三件事决定：

| 变量 | 影响 | 听觉表现 |
|---|---|---|
| **接触面积** | 面积大 → 低频多、能量摊薄 | 闷、厚、"拍" |
| **接触面硬度** | 硬 → 高频多、回弹明显 | 脆、亮、"敲" |
| **空气腔** | 有腔（鞋内、鞋底纹路）→ 挤气声 | 短促的"吱/噗"尾 |

由此得到三种脚的基线：

- **鞋**：硬底 + 中等面积 + 空腔 → 偏高、带一点弹、尾音干净。
- **光脚**：整掌肉垫、面积大、软 → 偏低偏闷，是"啪嗒"那种**拍**而不是"敲"。
- **爪**：接触面很小，几下轻触 → 短促发脆，常带一丝爪尖的刮擦/摩擦。

> 拟人化的例外要单独算。《喜羊羊与灰太狼》这类作品里，羊是拟人的，
> 懒羊羊平时不穿鞋，落地是"啪嗒"；灰太狼是爪直接着地，是轻脆的"嗒嗒"。
> 现实里羊是蹄行，但**动画设定优先于生物学**——按角色设定归类，不按物种。

## 2. 第二个维度：地面材质

同一只脚踩不同东西，变的是高频含量与尾巴长短：

| 材质 | 高频 | 尾巴 | 备注 |
|---|---|---|---|
| 木地板 | 中高，有共鸣 | 短回弹 | 老房子最常见，适合做基准 |
| 地毯 | 几乎无高频 | 无尾巴，只有闷响 + 摩擦 | 最容易做出"被吸掉"的对比 |
| 瓷砖/混凝土 | 亮、硬 | 更长，可能有轻微回声 | 冷、空旷 |
| 金属网格/铁板 | 亮且带金属共振 | 中长，有"嗡"的余韵 | 恐怖场景常用 |

所以声音的键不是"一个脚步声"，而是 **`脚部种类 × 地面材质`** 的二维表。

## 3. 数据结构（落地时照这个写）

放在 `文字剧情/音效表.json`（或原型独立的音频表）。示意：

```json
{
  "脚步默认": "光脚/木地板",
  "脚步": {
    "鞋":   { "木地板": ["sounds/step/shoe_wood_1.wav", "shoe_wood_2.wav"],
              "地毯":   ["sounds/step/shoe_rug_1.wav", "shoe_rug_2.wav"] },
    "光脚": { "木地板": ["sounds/step/bare_wood_1.wav", "bare_wood_2.wav"],
              "地毯":   ["sounds/step/bare_rug_1.wav", "bare_rug_2.wav"] },
    "爪":   { "木地板": ["sounds/step/claw_wood_1.wav", "claw_wood_2.wav"] }
  }
}
```

**查表顺序（三级回退）**：精确命中 `脚部/材质` → 该脚部的默认（如同脚部第一个材质）
→ 全局 `脚步默认`。目的是：只做四种声音（鞋、光脚 × 木地板、地毯）也能跑全套地图，
缺的那种自动退化，不会静音，也不会因为漏配而崩。

- 角色属性里给一个 `脚部`（鞋 / 光脚 / 爪）；
- 每张地图给一个 `地面`（材质名），换房间就换脚步性格；
- 触发器是**每走完一格**（逐格移动天然提供节拍点），不是按时间轮询。

## 4. 抖动：让重复不变成发条（硬要求）

同一条 WAV 连播八次，人耳立刻听出机械感。落地时必须：

1. 每组准备 **2~3 条**备选，随机取一条（不按顺序循环）；
2. 叠加**音调 ±3%、时长 ±5%** 的随机微扰；
3. 长距离移动时允许**偶尔不播**（约 10% 跳过），比每次都播更像人。

这三条不做，前面所有材质/脚部区分都会被"发条感"盖掉。

## 5. 合成还是实录

结论：**这一层用合成，接口留成可替换**。

- 脚步声短（80–150 ms）、无音高、纯冲击+摩擦噪声，人耳判的是节奏与频谱包络，
  不是音色细节 → 合成能到九成。
- 合成的好处是**可参数化调参**：听感不对时说"高频太重"能直接调，而不是换一条波形。
  实录只能整体重录。
- 实录无可替代的是**环境本身**（房间混响、地板不平、每步细微差异）。这些放在引擎侧：
  混响按房间走 + 上面第 4 节的抖动。

例外：门轴吱呀、木头受力的呻吟、长句环境音这类**非冲击、带摩擦演化**的声音，
合成很难做出"偶发"的真实感，实录更值。

## 6. 落地流程：逐条试听，不批量生成

批量生成音效必然出一堆"不搭边"的东西——参数能凑出声音，凑不出氛围。
所以约定：

1. 一次只做一个声音；**出声前先报**：播什么、几段、多长（例："光脚踩木地板，
   单步 120ms，三条备选，播四秒"）。
2. 播完由人来描述感受（尖 / 闷 / 太干净 / 没有空间 / 像塑料敲铁皮）。
3. 按描述改参数重做，一轮一轮收窄，直到人说"就是这个"。
4. 定稿的写进音效表 + 资产仓 `sounds/step/`，**参数与听感描述一起记**，以后能复现。

第一批只要四个：`光脚/木地板`（基准）、`鞋/木地板`、`爪/木地板`、`光脚/地毯`。
其余等需要时再补。

## 7. 与玄铁侧的限制

- 短音安全：90 ms / 1984 样本实测 1~2 ms、内存增量可忽略（见 AGENTS「已知坑」7）。
- **长音频与逐样本合成不要在玄铁里做**：浮点长循环约 709 字节/轮线性上涨。
- 所以：WAV 由外部程序（`文字剧情/生成音效.py` 的 FM 路径，或独立脚本）生成，
  玄铁侧只 `加载音效` / `播放音效`。
