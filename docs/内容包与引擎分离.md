# 内容包与引擎分离

结论先说：**作者导出的是“内容包”，不是游戏程序；可执行文件由引擎方按平台发布。**

这不是我们发明的形态。网盘/QQ 群流传的 RPG Maker 系同人游戏就是这么走的——
一份引擎 + 多份内容包，四部曲就是四个内容包。我们照这个形态落地，只补两件
RPG Maker 那边容易翻车的事：平台别成单点、版本对不上要明确报错。

## 为什么分离

- **平台数从「作者 × 平台」降成「引擎 × 平台」**。作者在 Windows 上做游戏，
  不再等于 Mac/Linux 玩家玩不到——他发的是数据，三平台读的是同一份。
- **改剧情不用重编**，内容包可以单独更新、单独分享。
- **体积与版本**：一份引擎可以带多个内容包（四部曲共用一份），换平台只替换引擎。
- **IP 边界**：引擎与引擎原创图块/音效可公开分发；角色精灵图、同人音乐属于衍生
  内容，只能由作者私下分发，**不进公开仓库**。

## 目录约定

```
游戏/
  引擎/                 ← 官方二进制，按平台各一份（换平台只替换这一层）
    play
  第一部/
    内容包.json
    剧情/               ← 幕NN.json + 目录.json
    资产/               ← 作者的素材，中文命名，按类型分子目录
      图块/
      角色/
      音效/
      音乐/
  第二部/
    ...
```

命名约定：

- 内容包内一律用中文目录：`剧情/`、`资产/`，子目录 `图块/`、`角色/`、`音效/`、`音乐/`。
  玄铁不做 i18n，中文是唯一语言，目录名没理由用英文。
- 仓库根的 `assets/` 是**克隆的美术素材仓库**（gitignore），与内容包里的 `资产/`
  不是一回事，保持原样不动。
- 资产路径全部相对内容包根（`资产/图块/…`），不认绝对路径，不认平台路径分隔符。

## 内容包.json

```json
{
  "格式": 1,
  "引擎": { "最低": "1.2", "开发于": "1.3" },
  "作品": "我还会回来"
}
```

字段就这四个，别再加：

| 字段 | 用途 |
|---|---|
| `格式` | 内容包格式版本。引擎不认识就直接报错，不半读 |
| `引擎.最低` | 低于这个版本的引擎不许打开 |
| `引擎.开发于` | 作者开发时用的版本，仅供排查，不参与拦截 |
| `作品` | 标题，播放器列内容包时显示 |

**不逐文件列资产清单。** 清单和实际文件一漂移（改名、补图）就是坑，且每次加图
都要改清单。引擎按剧情里引用的路径去 `资产/` 下加载，缺哪个报哪个。

## 音效的两类形态

音效不一定是文件。它有两种形态，**都在内容包里，但只有一种进 `资产/`**：

| 形态 | 写在哪 | 性质 |
|---|---|---|
| 成品 wav | `资产/音效/*.wav`，剧情里用 `音效.文件` / `音效.序列` 引用 | 文件，逐字节稳定、跨版本可复现 |
| 参数配方 | 剧情 JSON 的 `音效` 字段里（`毫秒` + `频率` + `选项`） | **不是资产文件**，是配方；引擎在节点进入时现场合成，播完即弃，不落盘 |

判据仍然是"运行时能不能被路径引用"：wav 是文件，进 `资产/`；配方没有路径，它属于
剧情本身，不进 `资产/`。

选型建议：**关键音效（门、死亡、心跳）用 wav，氛围与抖动类用配方。** 前者一旦定稿
就不该变；后者本来就要反复调，配方在 JSON 里可读可 diff，让 Agent 改一句参数就够。
代价是参数音色的上限受合成器限制（正弦/三角/锯齿/方波/白噪 + ADSR/EQ/延迟/混响），
且不同引擎版本可能渲染略有差异——所以不要把它当"可复现的成品"。

## 版本检查规则

引擎启动读内容包时只做两件事：

1. `格式` 不在引擎支持范围内 → 直接拒绝，并说明支持哪个格式。
2. `引擎.最低` 高于引擎自身版本 → 拒绝，并给出“请用 ≥X 的引擎”的提示。

**只承诺数据格式层面兼容，不承诺行为兼容**：剧情 JSON 字段只增不删，引擎读到不
认识的字段当作没看见；引擎太老、必需字段缺失时明确报错。这条比“保证兼容”诚实，
也真的能测。

## 玩家侧流程

1. 解压内容包（普通 zip）。
2. 拿对应平台的引擎（固定下载入口，按平台分类，版本号写清）。
3. 把内容包放进 `游戏/` 下，用引擎打开它。

作者若怕玩家找不到引擎，**在内容包里放下载链接，不放二进制**——二进制会过期，
链接不会。
