# 存档系统与存档界面：现状核对 + 玄铁侧设计

## 1. 三处现状（实测，别互相混淆）

| 位置 | 有没有存档 | 说明 |
|---|---|---|
| 玄铁原型 `原型/图块地图.xt` | **完全没有** | `docs/设计待落地清单.md` 里就写着"存档：未做，格式未定" |
| Rust Bevy 版 `src/save.rs` | **数据层有** | `SaveManager`：`create_save` / `list_saves`，存档落 `saves/*.json` |
| Rust Bevy 版 `src/game_ui.rs` | **界面骨架有，数据没接** | 见第 2 节，两列是常量占位 |
| Rust `docs/features.md` | **愿景大于实现** | 进度百分比、两种排序、备注、删除、自动备份，代码里都没有 |

Rust 版 `SaveData` 字段（这是真实现，可作为字段口径参考）：

- `save_id`：**玩家可见的存档 UID**，7 位小写十六进制哈希（设计口径：比 UUID 短、
  玩家能抄、能报"我那档是 3f7a91c"），由快照算 SHA-256 再截短。
  实现偏差两处（`src/save.rs`）：`result[..7]` 是 7 个字节经 `{:02x}` 拼出来，
  实际 **14 个字符**不是 7 个；且哈希输入只含位置/恐惧/理智/钥匙/死亡/怪物，
  **不含任何时间**，同一状态存两次会得到同一个 ID、互相覆盖——要当 UID 用就得
  加时间或计数进哈希。
- `game_duration`：游戏内时长，格式 `"Xh Ym"`；
- `real_time`：现实保存时间，`"YYYY-MM-DD HH:mm"`；
- `game_state`：玩家坐标、恐惧等级、理智值、钥匙数、怪物状态（位置+状态码）、
  游戏秒数、死亡次数、最近死因、最近检查点、**已揭示 tile 坐标**（探索记忆）。

## 2. Rust 版存档界面长什么样（照代码还原）

全屏页面，底色 `rgb(0.02,0.02,0.04)`（近黑），左右内边距 60、上 80、下 60，
整体纵向居中排布：

1. **标题**：一个 160×80 的方框，2px 灰边（`0.6,0.6,0.7`），框内 36px 白字「存档」。
   它是"按钮样式"的标题，不是纯文字。
2. **表格**（宽占 80%）：
   - **表头**：高 50，2px 边框，底色 `0.08,0.08,0.12`，22px 白字，四列等宽：
     `进度` | `场景` | `游戏时间` | `存档ID`，列间竖线 2px；
   - **每行**：高 45，2px 边框，底色 `0.05,0.05,0.08`，20px 淡蓝白字，列内文字居中；
   - **空态**：没有存档时显示一行居中的灰字「暂无存档」。
3. **底部提示**：40px 上边距，20px 淡蓝字——
   「按 ESC 返回 / 按 回车 或 点击 读取选中存档」。

**但它现在是半成品，两处硬伤 + 一处实现偏差：**

1. **「进度」和「场景」两列是常量**：`SLOT_NAME = "喜羊羊"`、`SCENE_NAME = "无尽回廊"`，
   每行都印同样的两个字，跟存档内容无关。
2. **没有缩略图、没有"存档 / 读档"模式区分、没有新建与覆盖的视觉差别**：
   标题永远写「存档」，回车就把选中档读掉。
3. **ID 列本身是设计意图，不是多余的**：7 位哈希就是玩家可见的存档 UID（同
   UID 那种唯一标识，只是短到能抄、能念）。问题只在实现——截出来是 14 位，
   且不含时间导致同状态重复存会撞 ID，见第 1 节。

## 3. 玄铁侧设计：竖排槽位卡片（哈希照显示）

理由：一档要同时给出"在哪、多久、什么时候存的、长什么样"和"它的 UID"，
缩略图是选档时最有效的信息，宽表放不下；但哈希这一列**保留**，
只从独立一列改成卡片右上角的小字位。沿用现有菜单语言
（左侧红杠 + 边框提亮，见主菜单/暂停菜单）。

```
        存 档
  ┌────────┬──────────────────────────────────────────────┐
  │ [缩略图]│ 槽 1   地下走廊 · 第二幕          #3f7a91c   │
  │ 128×96  │ 游戏 0h 42m   现实 11-27 21:04              │
  └────────┴──────────────────────────────────────────────┘
  ┌────────┬──────────────────────────────────────────────┐
  │ [缩略图]│ 槽 2   配电间 · 第三幕            #b41e0d2   │
  │         │ 游戏 1h 12m   现实 11-26 22:31              │
  └────────┴──────────────────────────────────────────────┘
  ┌────────┬──────────────────────────────────────────────┐
  │  空    │ 槽 3                                         │
  └────────┴──────────────────────────────────────────────┘
      W/S 选槽 · 回车 存/读 · Delete 删档 · Tab 换「存/读」 · ESC 返回
```

- **哈希要显示**：每张卡片右上角 `#3f7a91c` 这类 7 位小写十六进制，玩家能读、能抄、
  能报"我那档是哪个"。它是存档 UID，不是装饰，也不是只给程序看的东西。
  生成输入必须含现实时间或递增计数，否则同状态两次存档会撞同一个 UID。
- **6 个槽位**竖排，一屏放得下 6 张卡片（每张高约 90，含缩略图 128×96 等比缩放）。
- **缩略图**：存盘瞬间用 `R.截图` 截当前帧，缩到 128×96 存成 `saves/槽1.png`。
  这正是引擎截图那条路的正当用途：不带标题栏、尺寸确定、像素干净。
- **模式**：标题写「存档」或「读档」，由进入方式决定（暂停菜单/主菜单各给一项）；
  存档模式下空槽可选、读档模式下空槽灰掉不可选。
- **选中态**：左侧 6px 红杠 + 边框提亮 + 行底色略升一档，和主菜单一致。
- **空槽**：只画框和「空」字，不显示时间与缩略图。
- **删档**：Delete 两段确认（第一次变红字「再按一次删除」，3 秒无操作复原）。
- **损坏档**：读不出来时整行灰掉，右侧标「损坏」，不参与回车。

## 4. 存档数据（玄铁侧格式草案）

```json
{
  "版本": 1,
  "槽": 1,
  "哈希": "3f7a91c",
  "图": "原型/地图02.json",
  "玩家格": { "横": 7, "纵": 5 },
  "幕": 2,
  "场景名": "地下走廊",
  "游戏毫秒": 2520000,
  "现实时间": "2026-11-27 21:04",
  "缩略图": "saves/槽1.png",
  "已揭示": [[8,5],[7,5]]
}
```

- **时间存整数**（`游戏毫秒`），不存浮点：`docs/事件树视图设计.md` 已经写明
  "若将来要落成 JSON 存档，必须先转成整数标度"，浮点在存档里不稳。
- 一切可变字段都带 `版本`，读档时版本不符就拒绝并提示，不做静默兼容。
- `已揭示` 是探索记忆：`docs/绘制层级与视觉覆盖.md` 说明"要做就得连存档一起做"，
  做半截（读档后探索成果全丢）比不做更糟。

## 5. 与现有引擎的衔接点

- 新场状态 `场状态 == 6` = 存档界面；`docs/绘制层级与视觉覆盖.md` 里模态层第 6 层
  留给"主菜单、ESC 暂停、设置、存档"，层级上它吞世界输入。
- 字体参考串必须加：`存档 读档 槽 空 损坏 删除 再按一次删除 游戏 现实 幕 新`，
  以及 `0123456789h m-:` 这些数字与符号——**漏字即问号**（已知坑 4）。
- 存盘只在"画面静止"时做（暂停或存档界面），不放战斗/追逐中，
  与 `docs/天气-雨与雪.md` 的"静止时刻才用得起截图"结论一致。

## 6. 仍未定（要人拍板）

1. 槽位数量：6 固定，还是"自动存档 1 + 手动 5"。
2. 是否要"继续游戏"直接读最近一档（Rust 版开始界面有，玄铁主菜单目前只有开始/退出）。
3. 存档目录：项目内 `saves/`（Rust 版做法）还是用户目录（多项目共用时要分开）。
4. 是否存"已揭示 tile"（目前迷雾与手电都还没接进图块原型，先留字段不填也行）。
