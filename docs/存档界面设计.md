# 存档系统与存档界面

## 1. 三处现状

| 位置 | 状态 | 说明 |
|---|---|---|
| 玄铁原型 `原型/图块地图.xt` | **已实现 v1** | 六槽存档 + 存档/读档界面，数据落 `saves/槽N.json` |
| Rust Bevy 版 `src/save.rs` | 数据层有 | `SaveManager`：`create_save` / `list_saves`，存档落 `saves/*.json` |
| Rust Bevy 版 `src/game_ui.rs` | 界面骨架、数据没接 | 「进度/场景」两列是常量 `SLOT_NAME="喜羊羊"`、`SCENE_NAME="无尽回廊"` |
| Rust `docs/features.md` | 愿景大于实现 | 进度百分比、两种排序、备注、删除、自动备份，代码里都没有 |

Rust 版 `SaveData` 字段（作为口径参考）：

- `save_id`：玩家可见的存档标识，7 位小写十六进制哈希。主要作用是唯一标识一档
  （两段时间都分不开时由它兜底），短只是附带好处。实现偏差两处：`result[..7]`
  经 `{:02x}` 实际出 **14 个字符**；哈希输入不含时间，同状态存两次会撞号。
- `game_duration`：游戏内时长，`"Xh Ym"`；
- `real_time`：现实保存时间，`"YYYY-MM-DD HH:mm"`；
- `game_state`：玩家坐标、恐惧、理智、钥匙、怪物状态、游戏秒数、死亡次数、
  最近死因、最近检查点、已揭示 tile 坐标。

Rust 版存档界面按代码还原：全屏近黑底，顶部 160×80 按钮式标题框「存档」，
下面宽 80% 的四列表格（表头 50 高、行 45 高：`进度 | 场景 | 游戏时间 | 存档ID`），
空态一行灰字「暂无存档」，底部提示「按 ESC 返回 / 按 回车 或 点击 读取选中存档」。

**原设计没有缩略图，以人为准。** 判断一档靠两段时间（现实保存时间、游戏内时长），
两段时间还分不开时，由 7 位哈希兜底当唯一标识。所以界面是纯文本列表。

## 2. 玄铁侧已实现的样子

```
                    存档
 ┌──────────┬──────────────┬────────────┬─────────────┐
 │   进度   │     场景     │  游戏时长  │    标识     │
 ├──────────┼──────────────┼────────────┼─────────────┤
 │   玩家   │  一号走廊    │   0h 02m   │   #f32fe7b  │
 ├──────────┼──────────────┼────────────┼─────────────┤
 │    空    │     空       │    空      │     空      │
 └──────────┴──────────────┴────────────┴─────────────┘
   现实 2026-11-27 02:33
   W/S 选档  回车 存/读  Tab 换模式  Delete 删档  ESC 返回
```

- 四列宽 150 / 200 / 140 / 150，表头高 40、行高 44、行距 6；六槽一屏放下。
- 选中行：左侧 4px 红杠 + 边框提亮 + 底色升一档，与主菜单同一套语言。
- 空槽只画一行居中灰字「空」，不显示时间与标识；读档模式下回车会提示"这一档是空的"。
- 标题随模式变：从暂停菜单进来是「存档」，从主菜单进来是「读档」；
  屏内按 Tab 也能换，Tab 一按标题立刻变，玩家不用猜回车是覆盖还是读取。
- 现实时间不占第五列（会把宽度吃光），放在表下随选中档显示。
- Delete 两段确认：第一次底部提示「再按一次确认删除」，3 秒内再按才真删。

## 3. 操作与入口

| 键 | 作用 |
|---|---|
| W / ↑、S / ↓ | 选槽（循环） |
| 回车 | 存模式下写入当前槽；读模式下载入选中槽并回到世界 |
| Tab | 「存」↔「读」互换（标题跟着变） |
| Delete | 删档（两段确认） |
| ESC | 回到进入前那一层（暂停菜单或主菜单） |

入口：主菜单第 2 项「载入存档」（读模式，来源=主菜单）、暂停菜单第 2 项「存档」
（存模式，来源=暂停）。主菜单第 1 项「开始」会把图重置回 `原型/地图01.json` 起点、
已玩时长清零——不重置的话，读过档再点开始会沿用上一张图。

## 4. 数据（`saves/槽1.json` … `槽6.json`）

```json
{
  "版本": 1,
  "槽": 1,
  "标识": "f32fe7b",
  "进度名": "玩家",
  "图": "原型/地图01.json",
  "场景名": "一号走廊",
  "玩家格": { "横": 2, "纵": 8 },
  "游戏毫秒": 123456,
  "现实时间": "2026-11-27 02:33",
  "已揭示": []
}
```

- **标识**：7 位小写十六进制。输入是 `现实秒 + 已玩毫秒/1000 + 玩家格横纵`，
  过一遍线性同余再逐位取 hex——够用、够短、同一状态连存两次也不会撞号；
  它不是加密哈希，防的是"看起来一样的两档分不清"，不是防篡改。
- **游戏毫秒存整数**，不存浮点（`docs/事件树视图设计.md`：落 JSON 存档必须先转整数标度）。
  只在世界态累加；菜单、暂停、存档界面都不走游戏时钟。
- **现实时间**：`时.现()` 的 Unix 秒手算成 `YYYY-MM-DD HH:mm`（`civil_from_days`），
  固定按 **UTC+8** 出串。跨时区要改成按系统时区，得先有取时区的接口。
- **场景名**：先由引擎里的 `场景名表` 按图路径映射（`一号走廊/二号走廊/三号走廊`，
  暂定名）。真名定了只改那张表，不动存档格式。
- `版本` 不符或解析不出的档按空槽处理（不崩、不静默兼容）。
- `已揭示` 暂时写空数组：迷雾还没接进原型，字段先留着，接的时候直接填。

## 5. 与引擎的衔接

- 新场状态 `场状态 == 5` = 存档界面（0 主菜单 / 1 世界 / 2 暂停 / 3 说框 / 4 提示屏）。
  它全屏绘制并吞掉世界输入。
- 字体参考串补了 `存档 读档 载入 槽 空 玩家 号 未知 返 …` 与 `0123456789abcdefhm:-/#|.`——
  **漏一个字就是问号**（已知坑 4，第一次实测就踩到「??」「一?走廊」「ESC ?回」）。
- **一帧只截一张图**：渲染库同一帧内连调两次 `截图`，只有最后一次落盘，前一次静默丢弃。
  所以引擎加了 `本帧已截` 标志，自检与按需截图不会互抢。
- 存盘只在画面静止时发生（暂停/存档界面），与 `docs/天气-雨与雪.md` 的结论一致。

## 6. 验证

```bash
bash scripts/build-图块原型.sh          # 门禁：地图/门校验 → 抓 IR → 链接出 ./tilemap
touch /tmp/tilemap-存档自检 && ./tilemap    # 写槽1 → 读回 → 载入 → 写槽6 → 删 → 截图存档屏
```

自检输出（实测）：

```
【存档自检】写入 真 saves/槽1.json
【存档自检】槽1 标识=f32fe7b 场景=一号走廊 时长=0h 02m 现实=2026-11-27 02:33
【存档自检】载入 真 图=原型/地图01.json 格=2,8
【存档自检】删除后为空 真
```

截图 `/tmp/存档屏.png` 是引擎自己拍的渲染窗口（无标题栏、无红绿灯）。

## 7. 还没做（明确边界）

1. 自动存档位（死了/换幕时自动存一档）、存档缩略图——都不在原设计里，先不做。
2. 「继续游戏」直接读最近一档：主菜单目前是「开始 / 载入存档 / 退出」三项。
3. 备注、排序、备份：Rust `features.md` 里的愿景，v1 不做。
4. 跨时区、多存档目录、云同步。
