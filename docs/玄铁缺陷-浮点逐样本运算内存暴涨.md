# 玄铁缺陷记录：浮点逐样本运算导致极慢并吃爆内存

> 状态：**实测，未上报**。2026-11-21 在本仓库做 FM 音频合成时撞到；
> 结论是"这台语言不适合在运行时逐样本算 PCM"，但现象本身大概率是可修的编译器/运行时问题。
> 如果以后有人问"玄铁有没有缺陷"，这条可以直接拿出来；也可以原样转达上游。

## 1. 一句话结论

在**单个函数内的长循环里反复做浮点运算 + 数学函数调用**，玄铁的耗时会从"毫秒级"退化到"分钟级并最终被系统杀掉"，
表现不是报错，而是**内存持续增长后被 SIGKILL（exit 137）**。

## 2. 环境

- 玄铁 `xtc` 1.0-rc.5，channel `rc`，target `darwin-arm64`
- 渲染库 1.3.11（仅用作音频设备与句柄，不含本缺陷）
- macOS arm64（Retina），本地实测

## 3. 最小复现

```text
// 目标：合成 90 毫秒 48kHz 单声道 PCM（4320 个样本）
设 率 = 48000
设 样数 = 4320
设 个 = 0
当 个 < 样数 {
    设 时秒 = 个 / 率
    设 值 = 数学.正弦(6.2831853 * 1200 * 时秒 + 2.5 * 数学.正弦(6.2831853 * 1200 * 1.41 * 时秒))
    设 衰 = 数学.幂(2.718281828, 0 - 时秒 * 1000 / 30)
    值 = 值 * 衰 * 0.5
    设 样 = 整(值 * 32767)
    若 样 < 0 { 样 = 样 + 65536 }
    写数(信, 样, 2)      // 字节.追加(n)，每次 1~2 次方法调用
    个 = 个 + 1
}
```

`写数` 就是 `信.追加(整(数) % 256)` 这样的字节流追加。

## 4. 实测现象

| 规模 | 期望耗时（同算法 python） | 玄铁实测 |
|---|---|---|
| 90ms 音频 = 4320 样本 | ≈ 0.01 秒 | 2 分钟以上未出结果，进程被 SIGKILL（137） |

- 卡在循环内部，不是编译慢（`xtc tie` 编译本身正常完成）。
- 没有 OOM 提示、没有 panic，只有系统级 kill，看起来像"程序跑着跑着消失了"。
- 同一段循环里把样本数减小（几百）就能跑完，说明是**按样本累积**的开销，不是单点慢。

## 5. 疑似原因（待上游确认）

1. **浮点结果装箱**：`数学.正弦` / `数学.幂` 返回的是 `XTValue`（boxed），每次调用都在堆/Arena 上分配一个对象；
   一个样本要算 2 次正弦 + 1 次幂 + 若干乘除，等于每样本十几个分配。
2. **Arena 不回收**：运行时有 Arena 分配器，短生命周期对象进 Arena 后不在循环体内释放，
   造成 4320 × N 个对象堆积 → 内存线性上涨 → 被系统杀。
3. 也有可能是 `字节.追加` 的每次方法派发（带类型检查）叠加，但单靠它撑不起这个量级。

现在的规避方案是"不做"，见下节。

## 6. 当前规避（本项目做法）

**不要在玄铁里逐样本合成音频。** 音频/大规模数值计算放外部工具生成，玄铁只做 IO：

- `文字剧情/生成音效.py` 用 python 的 `math` + `wave` 生成 FM 音效 wav（90ms 用时约 0.01 秒）；
- 玄铁侧只用 `渲染.加载音效(文件)` + `播音效(句柄)`。

附带的发现（可用）：`文字剧情/生成音效.py` 用的二进制写法在玄铁侧也能成立——
`设 信 = 字节(n)` + `信.追加(x)` + `文件.写(路径, 信)` 是**二进制安全**的
（实测 `1 / 2 / 255` 写出后字节原样为 `01 02 ff`），所以少量字节的 WAV 头拼接在玄铁里没问题，
卡住的只有"逐样本的长数值循环"。

## 7. 建议给上游的修法

按优先级：

1. **纯局部浮点表达式不装箱**：函数内若变量未被逃逸（不存进数组/字典/返回到外部），
   编译成原生 `double` 运算，不走 `XTValue`。这能一次性解决绝大多数"算数字"的循环。
2. **循环作用域内回收**：Arena 支持 per-iteration 的临时区（类似 bump 回滚），
   让每轮循环的中间对象在下一轮开始前被回收。
3. **内置数学函数走快速通道**：`数学.正弦` 之类返回 `double` 而不是 `XTValue`。

若只能修一处，修第 1 条收益最大。

## 8. 复现清单（给上游）

```text
1. 新建空目录，写上面第 3 节的 xt 文件（补上与 写数 等价的字节追加）
2. xtc tie 复现.xt -sc 复现        // 编译应通过
3. time ./复现                     // 观察：超过 60 秒不出结果 → 复现
4. 用 /usr/bin/time -l ./复现 观察最大常驻内存（会看到持续上涨）
```

对照基线：同参数的 python 脚本应在 0.01~0.02 秒内完成。
