# 渲染：字体参考串、建字体与 Retina 光栅化

> 从 `AGENTS.md` 「已知坑」里拆出来的一节。只在**改界面文案、动字号、换字体**时看。
> 主干里只留摘要，细节以本文为准。

## 1. 参考串：没进串的字显示问号

绘制文本走 `加载字体精准`，**未进参考串的字符一律显示问号**，包括全角括号 `（）`、
`Q`、`_` 这类非汉字。

当前参考串由「三份剧情 JSON 全文 + 界面固定字串 + `剧情/界面.json` 的文案」拼成
（剧情与界面文案都自动覆盖），所以：

- 改剧情、改界面文案：不用手动补字，自动进串；
- 新增**引擎内部固定文案**里的符号（如 `；` `─`）：仍须补进那条固定字串，否则出问号。

## 2. 界面文案走 `剧情/界面.json`

标题、主菜单三项、暂停菜单三项都从这个文件读，启动时自动并入参考串，作者写什么字都能显示；
缺字段回退内置默认值。按键提示、机制提示、错误反馈属于引擎，**不放**该文件。

该文件另有两个字段：

- `字体`：字体文件路径。发布版应换 SIL OFL 字体自带分发——
  渲染桥不支持 ttc 里的 CFF/OTTO 首 face，**必须是单文件 TTF**；
- `补充字`：想把新写的引擎文案整句粘进来就能进字库，省得漏字出问号；
  实测 `※` `§` 这类符号也正常。

## 3. Retina：图集必须按「最大绘制字号 × 像素比」光栅化

渲染桥已设 `FLAG_WINDOW_HIGHDPI`，2x 屏上 40 号字实际占 80 物理像素。
若图集仍按 24 或 40 光栅化，标题放大会糊（肉眼就是"低分辨率/像素感"）。

- `渲染.xt` 没导出缩放系数，但桥里有 `XT_GetRenderWidth`：项目里自己声明
  `外 函 XT_GetRenderWidth(): 整`，用 `XT_GetRenderWidth() / R.取屏幕宽()`
  整数除得像素比（本机实测 = 2）；
- 图集字号取 `字体基准(=40) × 像素比`，其余字号按比例缩小绘制（缩小比放大小清晰）。

## 4. 唯一建字体入口：`建字体(路径, 参考串, 像素比)`

它内部取「所有字号档位的最大值 × 像素比」自动算光栅化字号，所以改 `字号标题`
等常量时图集分辨率会自动跟着走。

**不要再直接调 `加载字体精准`**——那一步最容易把 24 这种"显示字号"当成光栅化字号
传进去，Retina 上就糊。

字号档位集中在 `字号标题/字号菜单/字号正文/字号提示` 四个常量，绘制时不散写数字。

## 5. 版本差与将来的 API

- 本地分发包 `渲染.xt` 只有 `取屏幕宽()`，**没有**上游 master 已导出的
  `取缩放系数()`/`取渲染宽()`（上游 1127/1141/1154 行），所以项目里自己声明
  `外 函 XT_GetRenderWidth(): 整`。分发包更新后可改用官方导出。
- **上游若落地 `加载字体高清(文件, 逻辑字号, 参考)`**（内部自动 ×缩放系数），
  本项目应把 `建字体()` 退化成一行调用它，不要继续手算像素比——
  换算逻辑归库，应用侧只传「屏幕上看到多大」。
