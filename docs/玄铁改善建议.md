# 玄铁改善建议（汇总表）

> 用途：把本项目踩出来的"上游该改什么"集中到一处。想给玄铁提 issue 或找上游聊时，
> 从这里挑条目，不用满仓翻文档。每条只写**现象 / 现在怎么绕 / 建议 / 验收判据**。
> 状态标记：✅ 实测确认 / ⚠️ 实测确认但需复测（版本可能已变） / 📄 仅文档口径未实测。

## 1. 运行时与系统能力

| # | 现状 | 现在怎么绕 | 建议 | 验收判据 |
|---|---|---|---|---|
| 1 | 无系统熵入口：只有 `数学.随机`（底层 `rand()`）与 `数学.设随机种子`（`srand`），GUIDE 与 lib 里没有 `getentropy`/`getrandom`/`BCryptGenRandom` 封装 ⚠️（26.10.26 分发包） | `执("od -An -tu4 -N4 /dev/urandom")`，Windows 得换 powershell，跨平台难写 | 加 `系统.随机字节(个数)`（macOS `getentropy`/`arc4random_buf`、Linux/Android `getrandom`、Windows `BCryptGenRandom`），上面包 `系统.随机整数(上限)` | 同一进程连续取 1 万次，重启前后序列不重复；不再出现"每次启动同一串" |
| 2 | 无目录创建 API；`文件.写(路径, 内容)` 要求父目录已存在 | 启动时 `执("mkdir -p " & 目录)` | 加 `文件.建目录(路径)` 或让 `文件.写` 自动建父目录 | 直接 `文件.写("a/b/c.json", ...)` 成功 |
| 3 | `时.现()` 只有 Unix 秒；要毫秒 / 本地时间得自己算（存档的现实时间就是手搓 `civil_from_days` + 固定 UTC+8） | 自算公历换算，偏移写死 | 加 `时.现在毫秒()`、`时.本地时间(时区偏移)` 或 `时.格式化(格式)` | 能直接取到 `2026-11-28 14:03:07.123` 且时区正确 |
| 4 | `时.延时()` 编译通过、运行崩 | 自建忙等（`时.毫秒()` 轮询） | 修好或给出替代 API | 调 `时.延时(200)` 不崩且实际停约 200ms |

## 2. 渲染库：窗口与画面

| # | 现状 | 现在怎么绕 | 建议 | 验收判据 |
|---|---|---|---|---|
| 5 | 截图是"一帧一个槽位"：同一帧连调两次只有**最后一次**落盘，前一次静默丢弃且无日志；帧外调用打印 `[渲染库][错误] 截图 调用时机不对` 但仍保存 ✅ | 引擎加 `本帧已截` 标志，一帧只截一张 | 截图改为队列：同帧多请求按序落盘；帧外调用明确报错并失败 | 一帧内连截 3 张，3 个文件都在 |
| 6 | 截图只能整窗/离屏全幅，没有"指定矩形/只截世界区" | 先存全图再外部裁切 | 加 `截图区(路径, 横, 纵, 宽, 高)`（逻辑坐标，内部按像素比换算） | 800×600 窗口截 400×400 世界区，得到 800×800 物理图 |
| 7 | 创建窗口时没有选项，可调整只能在运行时 `设窗口可调整(真)` 开 ✅（实测能点亮 macOS 绿键） | 开窗后再调一次 | `初始化窗口` 增加选项参数（可调整/全屏/居中/无边框） | 一开窗绿键就可用，无需运行时代码 |
| 8 | 无"窗口尺寸变化"事件；拖拽/最大化/进全屏后 `取屏幕宽`、绘制坐标系是否同步未实测 ⚠️ | 每帧轮询比较宽高 | 加 `窗口尺寸变化?()` 事件或回调 | 拖大窗口后同一帧内读取新尺寸，界面重排正确 |
| 9 | 无第二窗口、窗口位置、置顶、渲染纹理（离屏画到纹理） | 单窗方案：世界区 + 外部 UI 带；或双进程转发按键 | 第二窗口 + 每窗绘制目标/输入焦点；或先给渲染纹理 | 两窗各自渲染、各自收到自己的输入 |
| 10 | 无显示器物理 DPI / 物理尺寸；`取渲染宽/取屏幕宽` 只给缓冲倍率，算不出毫米 | 只做"逻辑像素恒定"（1 格 ≈ 1.7 cm），跨屏会漂 | 加 `取显示缩放比()` / `取物理DPI()`，并给跨屏变化通知 | 换到不同缩放显示器，格子的毫米尺寸仍一致 |
| 11 | 全屏/最大化下无内容区查询（刘海、菜单栏、Dock 占位） | 自己做常数留边 | 加 `取安全区()` 返回内容矩形 | 刘海屏全屏时世界区不被压边 |

更细的截图实验与 A–G 建议见 `docs/渲染库-截图能力建议.md`；窗口两种模式与自适应诉求见
`docs/方形画面与UI分离.md` 第 2 节。

## 4. 上报时怎么用这张表

- 挑**现象可复现**的条目，附上"现在怎么绕"——上游最容易接受"有替代方案还能证明是缺陷"的报告。
- 一条一 issue，别把窗口、熵、浮点混在一个 issue 里。
- 复测过的把 ⚠️ 改成 ✅，并写清分发包版本（如"26.10.26 分发包"）。
