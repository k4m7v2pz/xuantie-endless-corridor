# 素材与画面约束（默认兜住，别靠作者的手艺）

> 起因：B 站同人恐怖实况的共性毛病——主菜单 / 新游戏提示 / 过场 / 闪图常常
> 把 1:1 拉成 4:3、4:3 拉成 16:9；图一看就是画图（mspaint）里拼的；
> 地块直接用 RPG Maker RTP，精灵图互相摘；美羊羊永远歪着，因为所有人都用同一套
> 没人重画的素材。
>
> 这些**都不是引擎该交给作者去修的**。它们全部可以变成"引擎不接受、或者自动纠正"。

## 1. 比例：引擎不接受错误比例的三条路

原则：**画出来的比例必须等于源图比例**。引擎里只有三种合法处理，没有第四种：

| 处理 | 什么时候用 |
|---|---|
| 等比适配 + 留边（透明/黑边） | 图比槽大或小，槽位内居中，边由引擎补 |
| 等比裁切 | 图比槽长，且作者确认要裁（闪图、过场常用） |
| 报错 | 其他一切情况 |

**禁止**：非等比缩放。不管是为了"填满"还是"看起来刚好"。

槽位不靠人记，写成表（`槽位.json`），每项只有三件事：`用途`、`比例`、`最小边长`。
构建时由检查脚本读 PNG 头拿到真实宽高，比例不对就直接报错列出：

```
[比例不合] 素材/主菜单/标题.png  1000×1000 (1:1)  →  槽位 主菜单比例 16:9
```

这样"1:1 图拉成 4:3"这种错误在**出包前**就被拦下，而不是等玩家看着难受。

缩放一律**最近邻**：色块、像素画、RTP 图块一插值就糊成一片，糊了就像 mspaint。

## 2. 闪图：既要有冲击力，也不能把人闪出事

恐怖游戏闪图是真需求（吓人用的那一帧），但频率与时长必须有上限，这是硬约束而不是审美：

- **单次闪 ≤ 0.3 秒**；连续闪**不超过 3 次/秒**（光敏性癫痫的国际通行红线）
- **亮度跳变**：不要全白↔全黑的连续往复；一轮闪之后至少留 2 秒的暗场
- 闪图同样走等比规则（第 1 节），**"拉满全屏"不等于"非等比拉满"**
- 引擎提供 `减少闪图` 开关（可关掉高频闪烁，保留静态惊吓图）

## 3. 精灵：四向是规范，缺帧宁可画朝向杠

同人素材最常见的两件事：一帧顶四向、从别的游戏里摘一套就再没重画（于是"永远歪着"）。
引擎侧的口径：

- 精灵表按 **上/下/左/右 × 走/停** 登记，缺哪一档就走**回退链**：
  该向走 → 该向停 → 下向停 → 画朝向杠。
- **禁止"用一套图顶所有朝向"**：宁可显示一根朝向杠（我们在 2D 原型里已经在画），
  也不要画一个脸朝别处的角色——后者会让玩家读错朝向，进而读错"柜子的正面在哪"。
- 一条素材没重画不是引擎的错，但**"歪着还硬用"是引擎可以拒绝的事**。

### 3.1 两种"歪"要分开：朝向错 vs 造型斜

同人素材里"美羊羊老是歪着"其实不是朝向帧错，而是**四向都画了、但每一帧的画本身是斜的**
（头往一边偏，像被转了几度）。这两种问题的处理完全不同：

| 类型 | 是什么 | 引擎怎么办 |
|---|---|---|
| **朝向错** | 缺帧、或拿一帧顶四向 | 拒绝：回退链 → 朝向杠（可自动） |
| **造型斜** | 画本身偏轴，四向都一样斜 | 不能改图；**只能给校正参数**或容忍 |

引擎不许自动"掰正"精灵：自动旋转会连别的东西一起转，而且没人授权你改美术。
正确做法是**每帧可带 `偏移` 与 `旋转`**（默认 0），作者显式填，应用时只影响显示。

### 3.2 能不能机械查出"斜"：能，查一致性而不查审美

引擎算不出"头歪得像霍金"这种判断，但能算**几何一致性**，而它才是真正让人难受的部分：

- 每帧 alpha 包围盒的**底边线**（脚底）——四向之间是否对齐（跳动 > 1 像素就提示）
- 每帧包围盒的**水平中心**——左右朝向是否镜像对称
- 帧序列的**体积/面积**——走 vs 停是否突然胖一圈
- **头身轴线**：逐帧算上半身重心相对脚底点的横向偏移，比较四向的偏斜方向与角度是否一致

判据是**一致 > 正确**：四向都同样歪着 3°，玩家会当成画风；四向歪的方向各不相同、
脚底一跳一跳，才叫"坏"。所以体检报告只报"不一致"和"建议校正值"，
不报"这画得丑"——后者超出引擎职责。

产出形态：`原型/检查素材.py`（读 PNG 头即可算包围盒尺寸；需要逐像素时才解码）
输出每帧的底边线、中心偏移、建议 `偏移/旋转`，作者填进精灵表就正回来了。
这样"歪着"这件事从"只能忍受"变成"一条命令给出校正数字"。

> 顺带一条现实判断：这套"永远歪着的美羊羊"之所以传遍，是因为**没有人重画**。
> 引擎能给校正参数，但抄素材的源头质量问题，引擎兜不住也不该兜。

## 4. 素材来源与署名（登记，不代办授权）

摘别人素材这件事，引擎不做警察也不做律师（见 `docs/授权与合规问答.md`），
但可以做一件成本极低的事：**每个素材登记来源**。

```json
{ "文件": "sprite/mei_walk.png",
  "来源": "自绘 | 摘录",
  "作者": "<作者名>",
  "许可": "<许可名>",
  "地址": "<来源链接占位>" }
```

用途：出包时自动生成署名清单（木兰 OWL 要求署名），也给作者自己留个"这套图哪来的"。
**不登记也能跑**，但构建时给一条提示——不是拦，是提醒。

## 5. 画图的廉价感，能不能自动降一点

不做美术指导，只做三件机械的事：

1. **最近邻缩放**（第 1 节）：直接消灭"糊"这一类廉价感。
2. **统一色板**：引擎提供一份可选 `色板.json`，把过场/菜单图量化到同一套颜色，
   防止"每张图各调各的饱和度"。
3. **禁 JPG**：菜单图、闪图存 PNG。JPG 的块状压缩在暗场里特别脏，一眼就"画图做的"。

## 5.5 为"旁观者"优化：画面常被录下来给别人看

同人恐怖的实际观众结构是三层：**玩的人 → 录的人 → 看解说视频的人**。后两层看的是
**被视频压缩过的画面**，所以默认值要按"压缩后仍看得清"来定，标准比"本地显示器上好看"更严：

- **字高下限**：1080p 下正文 ≥ 24 px、提示类 ≥ 28 px（视频压缩会吃掉 1~2 px 的细笔画）；
- **对比度**：文字与底色对比 ≥ 4.5:1；暗场里的文字必须有**半透明背衬**，别靠纯白字压黑底；
- **禁止 1 px 细线做信息**（边框、分隔、指示都用 ≥ 2 px，暗场里尤其）；
- **HUD 疏**：同屏常驻信息不超过两处，解说画面里信息一多就乱；
- **不靠颜色单通道传达**（红/绿在压缩与色弱下都会糊），重要状态同时给形状或文字。

这一条与"默认即合格"是同一件事的两面：默认值不只服务玩家，也服务"这游戏被别人看见时"。

## 6. 落地顺序（都是小件，别一起上）

1. `槽位.json` + 构建期比例检查（读 PNG 头，不需要解码）—— 最便宜、收益最大。
2. 精灵缺帧回退到朝向杠（2D 原型已有朝向杠，接精灵时按第 3 节接）。
3. 闪图时长/频率钳制（参数写在配置里，超了引擎截断，不报错）。
4. 来源登记 + 署名清单生成。
5. 可选色板量化（放最后，属于锦上添花）。
