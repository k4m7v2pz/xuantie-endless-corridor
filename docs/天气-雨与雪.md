# 天气：雨与雪

## 现状

| 版本 | 情况 |
|---|---|
| Python 版（设计提案） | `rust-bevy-endless-corridor/docs/rain_system_proposal.md`：近景大雨滴 / 远景雨丝 / 地面溅射三层，另有室内外音效差异化与配置化参数 |
| Rust 版（Bevy） | `src/environment.rs` 有 `wind_direction`、`wind_speed` 字段，也生成了雨滴实体，但 `update_rain` **只改 y**——方向字段没接线，风吹不起来 |
| 玄铁版（本项目） | **完全没有**天气效果。`主函数.xt` 只有窗口、移动、地砖、暗角、手电筒 |

所以"下雪 + 左右飘"在玄铁这一侧是从零开始，不能指望从 Rust 版继承——那里连雨的方向都还没接上。

## 设计

一个天气参数就够，雨和雪共用同一套，只是取值不同：

```json
{ "类型": "雪", "数量": 160, "方向": 12, "速度": 0.6,
  "摆动幅度": 26, "摆动频率": 0.8, "大小": [2, 5], "透明": 0.75 }
```

字段含义：

- `类型`：`雨` / `雪`。雨是直线加斜率，雪是慢速 + 正弦横摆。
- `方向`：-90~90 度，正值向右。雨靠它做出风斜；雪靠它做整体漂移的偏置。
- `速度`：像素/帧（或每秒，实现时定一个单位，别两处混用）。
- `摆动幅度` / `摆动频率`：只对雪有意义——每片的横向偏移 = `sin(时间 × 频率 + 相位) × 幅度`，
  相位逐片随机，整场雪就不会"齐步走"。
- `大小`：像素区间，逐片随机，近大远小靠它模拟景深（不做 z 轴，只做尺寸差）。
- `透明`：0~1。雪在暗场景里要偏灰白且低对比，太亮会盖住手电筒的暗角。

## 实现要点（玄铁侧）

- 粒子是一个数组：`{ x, y, 速度, 相位, 大小 }`，进场景时按 `数量` 生成一次。
- 每帧：`y += 速度`；`x += sin(相位 + 时间×频率) × 幅度 + 方向`；越界（y > 下边缘）就回收到顶部随机 x。
- 用 `R.画矩形` / `R.画圆` 直接画，别上贴图——雪片的像素形状就够了，贴图反而要管图集。
- 透明走 `R.设透明度` 之类的接口（实际名字 grep `lib/渲染/渲染.xt` 确认，不要凭记忆写）。
- 数量控制在 100~200 之间。文本/地砖本来就不重，粒子不该成为新瓶颈。

## 与剧情的关系

天气属于渲染层，写在 `剧情/界面.json` 里（按幕或场景挂），由 `主函数.xt` 读入后生效；
剧情 JSON 不直接控制粒子，只声明"这一场要雪"。这样换剧情不用改引擎，关掉天气也不改剧情。

## 验证口径

渲染程序只能跑窗口验证：`rvs scripts/test-macos.rvs` 会构建并跑 4 秒后自动关闭。
判断标准是肉眼——雪片有没有左右飘、有没有齐步走、暗角里还看不看得见、帧率有没有掉。
**跑这个会短暂弹出一个窗口**，测试前先说一声。
